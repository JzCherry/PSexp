# 开发指南

本文中的路径均以 Git 仓库根目录为起点，即包含 `PSdodo/` 和 `编译.bat` 的目录。

完整产品行为、使用场景、脚本协议和配置字段见 [功能说明书](功能说明书.md)；介绍机器人与客服问答接入见 [AI 导览与问答](AI导览与问答.md)。两者按当前源码描述，发布包请核对对应版本。

## 构建与验证

需要 .NET 10 SDK。公开编译入口为 `编译.bat`，执行 .NET 自测后生成不包含 .NET 运行时的 Windows x64 单文件 EXE（运行需要 .NET 10 x64 Runtime），成品放在脚本旁边，中间文件写入 `%TEMP%/PSexp-compile/`。该入口默认不混淆、不裁剪，默认关闭单文件压缩（SDK 仅允许自包含发布启用），不执行 Releases 上传。

单独构建和运行 .NET 自测：

```powershell
dotnet build .\PSdodo\PSdodo.csproj -c Release
dotnet run --project .\tests\PSdodo.Tests\PSdodo.Tests.csproj -c Release
```

安装 Node.js 后，还可运行 UXP 脚本行为测试（`编译.bat` 不自动执行这两项）：

```powershell
node .\tests\PSdodo.Tests\uxp-layer-batch.test.cjs
node .\tests\PSdodo.Tests\uxp-receipt.test.cjs
node .\tests\DocumentEvents.test.mjs
```

这些测试模拟 Photoshop DOM 和文件系统，覆盖图层筛选、命名、可见性恢复、部分失败和完成回执。发布前还应在真实 Photoshop 文档中检查图片内容、五种模式和兼容性；界面修改需要检查不同 DPI、窗口尺寸及交互状态。

## 模块

- `PSdodo/Views`、`ViewModels`：窗口交互、页面状态和命令。
- `PSdodo/Services`：导出、设置、Photoshop 联动与窗口收纳。
- `PSdodo/Core`：COM / UXP 桥接、任务回执、脚本注入及日志。
- `PSdodo/Resources/Scripts`：嵌入应用的 Photoshop 脚本。
- `PSdodo/Styles`、`Controls`：共享设计 Token、组件样式和自定义绘制。
- `tests/PSdodo.Tests`：独立自测程序，应用不依赖此项目，不打包进正式 EXE。
- `references/photoshop-scripts`：历史参考，非当前应用的编译输入；判断实际执行逻辑应查看 `Resources/Scripts` 和调用代码。

## 导出行为

五种导出模式使用 UXP `.psjs`；文档与画板探测使用 COM / JSX。快速导出使用等待完成的整画布 `saveAs`；全部画板及选中画板保留画板导出流程。图层由 `layer_batch.psjs` 按 `LayerExportRecursive` 选择一级图层或图层模式，图层模式通过 `LayerExportSelectedOnly` 选择 Photoshop 当前选中项或全部叶子图层；原生切片由 `native_slices.psjs` 独立处理，禁止以遍历可见图层代替切片。

一级图层按完整画布逐主体合成，顶层组整体输出；显示的排除项与真正背景保留为公共合成内容，隐藏的保持隐藏。真正背景按 `isBackgroundLayer` 属性识别，不看中文名称。公共水印、边框和底图仍遵循原层级、父级、蒙版与混合关系；没有创建盖印层、自动裁边或自动排列组合主体/背景的步骤。具体组织示例和实现依据见 [功能手册第 06 节](功能说明书.md#layers)。

图层导出按初始快照筛选目标，递归模式跳过图层组及排除分支，仅导出叶子图层；在 `finally` 中从子层向父组恢复全部可见性。原生切片读取 Action Manager 的 `slices` 元数据，筛选用户及图层生成的图像切片，整批只创建一个可复用的合成副本；每片在历史挂起期间按原始坐标裁剪并保存，随后通过 `resumeHistory(..., false)` 恢复完整画布，不累计裁剪历史。模态任务结束时关闭副本一次；支持的宿主使用 `registerAutoCloseDocument` 保证取消后的清理。原文档不参与裁剪或历史回滚。导出完成后通过 JSON 回执报告成功、失败及实际输出数量。取消只停止应用等待，不能保证 Photoshop 已终止；取消或超时后不得立即删除 Photoshop 仍可能使用的任务文件。任务目录位于 `%TEMP%/PSexp/tasks/`。

保留的旧导出 JSX 不表示当前调用链会自动回退到它们。修改导出逻辑时应同时核对实际调用、脚本和回执处理。

## 维护要求

- 保留现有自测；新增可测试逻辑时补充有意义的行为测试。
- 组件遵循 [UI 规范](UI规范.md)，同类尺寸和状态优先通过共享 Token / 样式修改。
- Photoshop 动态 COM / DOM 不适合随意启用裁剪；默认稳定发布关闭裁剪。
- 运行日志写入 `%LOCALAPPDATA%\PSexp\Logs\psx.log`。日志包含导出参数、任务编号、临时脚本与回执路径、执行结果和完整异常；失败任务文件会保留以便排查。上传日志或截图前检查个人路径与文档名称。
- 源码、测试、构建配置和有用的开发文档纳入 Git；构建产物、日志、账号凭据和个人工作记录不纳入 Git。
- 用户下载的 EXE 通过 GitHub Releases 附件分发，源码 Push 不会自动生成或上传 EXE。

作者本地外层目录中的发布脚本和内部历史记录不属于本仓库；克隆仓库后使用公开编译入口即可构建。

## 自动更新

`Services/UpdateSignature.cs` 以嵌入公钥强制验证清单签名，只从认证 payload 创建不可变元数据；`Services/UpdateService.cs` 负责受限 HTTPS 清单、流式下载、大小/版本/SHA256 校验及退出后的原子替换。`ViewModels/MainViewModel.Updates.cs` 负责自动检查、后台下载、手动安装、状态和取消。设置页及设置按钮上的更新提示由共享样式承载，更新过程写入 `%LOCALAPPDATA%\PSexp\Logs\psx.log`。

目录开发版通过编译脚本更新；自动安装只适用于单文件发布版。客户端代码不包含 SSH 凭据；上传逻辑和本机连接配置位于仓库外层 release-tools/。服务器清单与包必须最后一致发布，不允许先发布清单再传 EXE。
完整签名协议、公开构建与私钥边界、发布机换机限制及服务器隔离见 [更新安全与发布签名](更新安全与发布签名.md)。源码仅包含公钥资源和公开签名工具，私钥位于本机 AppData 外部保管；当前未编译的新代码不会改变既有旧 EXE 的验证行为。

## 文档识别失败与 COM 连接

本机 2026-11-02 的失败根因已实测：Photoshop 是普通权限（完整性级别 8192），PSexp 是管理员权限（12288）。管理员 PSexp 的日志显示 ROT 空、GetActiveObject 返回 0x800401E3，新增的 CoCreateInstance 又等待约 30 秒后返回 0x80080005；在普通权限进程内直接加载同一份 PSexpV3.dll，通过真实 WindowsComBridge 和 document_info.jsx 连续三次读取均成功（290/58/59 ms，文档“未标题-1”，4000×4000）。这是当前机器的实测结果，不代表其他环境的唯一失败原因。

启动时在单实例和界面创建之前检查权限。如果当前 PSexp 为管理员权限、同账号同会话的 Photoshop 为普通权限，取得当前账号同会话的普通权限桌面进程令牌，严格核对用户 SID、会话和完整性级别后复制为主令牌，使用该账号的环境块重新启动同一程序，并退出高权限启动进程。保留原生命令行，内部标记最多允许一次重试，不改变 Photoshop、不切换账号、不索取密码、不提高权限。原先使用 UAC 关联令牌的方案在本机实际报 1346，已替换；错误日志现包含 desktop-token 策略及失败阶段。2026-11-02 已经真实管理员启动验证：高权限启动进程成功切换为普通权限运行，后续多次 COM 文档识别及用户手动刷新正常，本次新会话无外部 UXP 文档探针派发。Photoshop 本身为管理员权限、不同用户或未检测到 Photoshop 时，不自动降低当前权限。

COM 连接先核对两个程序的用户和完整性级别，不匹配时立即给出明确错误，再按注册名称 GetActiveObject 或通过 ROT 接口及安装路径获取已有对象。撤销上一轮 CoCreateInstance 备用入口，避免跨权限等待和意外服务器启动；自动识别依然不调用外部 UXP、不创建新 Photoshop、不做定时轮询。日志新增 [permissions]，记录两个程序的权限、自动切换结果和失败原因。编译脚本是 asInvoker，可能继承管理员终端权限；这不是 Photoshop 未打开文档。

自动读取失败时，如当前 Photoshop 进程已有成功识别结果，保留文档名、尺寸等上次信息，并明确标记“同步中断”和“上次识别”；这不代表当前文档已确认有效。导出仍先执行主动识别，识别失败或确认无文档即停止，不使用旧信息继续导出。没有成功结果、Photoshop 退出/进程改变或导出前识别失败时清空旧状态。手动刷新和自动识别只通过 COM 内部读取，不因连接失败打开外部 UXP 脚本。只有用户主动导出前，才允许 COM 失败后使用 UXP 备用识别。权限不一致时显示明确的重新打开提示，不用“同步中断”代替具体原因。

### COM 不可用时的 UXP 识别

若运行实例也无法通过 COM 获取（例如 0x800401E3），仅主动导出前识别允许 PhotoshopService 在当前进程内切换到独立 UXP 文档探针 document_info_uxp.psjs，通过 document.json 读取文档名、像素尺寸、完整文件路径、画板与原生切片信息。UXP 完整文件路径转换为父目录后才进入既有输出位置模型；云标识/未保存文档不冒充本地目录。这个探针不创建、保存或关闭 Photoshop 文档。

前台识别调用 `ProbeDocumentInfoQuietlyAsync`，在 STA 内经 `WindowsComBridge.DoJavaScript` 运行只读 JSX 并直接取回 JSON，不使用 `.psjs` 文件关联。首次激活和动画结束后的检查要求主窗口真实前台，每次激活仅一次；忙碌时不重入。自动路径与主动 UXP 回退分离，不添加定时刷新、键盘钩子或焦点恢复操作。

切片 `FileName`/`SliceFilePrefix` 默认空，前缀不参与导出可用性判定；显式输入和清空均保存。原生切片脚本只在非空前缀后追加下划线，空值直接使用切片名或序号。

## 参数记忆与切片子文件夹

AppSettings 保留历史 default 前缀字段作为上次路径/格式/质量，补存 LastExportMode、LastArtboardPathOption、QuickImageName、LayerImagePrefix、SliceFolderName、LastSettingsSection 与 ShowSettingsOnStartup。完整快照写入所有当前用户参数，名称分模式存储；清空不被启动兜底改写。MainViewModel.ParameterMemory.cs 对连续输入使用 250ms 保存合并，窗口失焦/关闭调用 FlushParameterMemory。PNG 启动同时恢复 IsJpgFormat，避免质量行显隐与格式不一致。新增设置字段必须同时抄进 `MainViewModel.CreateAppSettings()`：该方法整体覆盖 `settings.json`，漏抄后随便一次自动保存就把新字段抹回默认值。

切片文件夹为可选单级名称，校验后在输出根目录组合路径；ExportSlicesAsync 复制本次参数并用实际目录执行，不污染用户保存的根目录。空值直出、同名文件夹复用、文件冲突按原策略处理。新控件复用现有输入样式，错误就地显示。不恢复任务过程或 Photoshop 实时状态；未编译测试。

## 前台识别与输入行为

取消文档同步定时器、文档身份轮询和空闲校准，删除 `PhotoshopFocus` 中的最后输入时间与按键状态检查。源码只在主窗口句柄上注册一枚用户自定义的全局唤起热键（`MainWindow.GlobalHotkey.cs` 调 `RegisterHotKey`，`WM_HOTKEY` 由既有 WndProc 子类接收后再投递到 UI 线程），不安装键盘/鼠标钩子，也不注入按键。热键不设独立开关：`summonHotkey` 为空即不注册，注册与否只由这一份字符串决定。「唤起跟随鼠标」的落位算法在 `Services/SummonPlacement.cs`（纯函数，只吃物理像素的矩形，便于自测），调用点在 `MainWindow.Placement.cs` 的 `MoveBesidePointer`，只在这次唤回动作里读一次 `GetCursorPos`，不轮询鼠标；`ActivateFromExternalRequest` 的 `keepWindowPosition` 参数只给“不是把窗口叫过来”的入口传 `true`（启动位置恢复、导出指令窗口试运行让位），真正的唤回入口沿用设置。文档自动识别只由 PSexp 主窗口获得前台焦点触发，持续前台、后台、隐藏或仅悬停展开均不循环读取；自动路径只允许 COM 内部调用，不启动 UXP 外部任务。

设置页移除检查间隔，只保留“前台识别”开关，继续使用 `AutoRefreshOnActivated` 记忆偏好。删除 `DocumentSyncIntervalMs` 和历史 `PollingIntervalMs` 字段；旧 JSON 的未知字段由现有反序列化机制忽略，下次保存自然清除。状态动画、贴边感应和软件更新的计时器用途不同，继续保留。

窗口失活时只清编辑逻辑焦点，不调用窗口 Focus 抢回键盘焦点。手动刷新和主动导出属于用户操作，仍会识别文档。以上为源码修改，尚未实机验证快捷键恢复情况。

## 实验性文档事件接入

前台成功识别后可注册 Photoshop Notifier；回调只写变化标记，C# 使用系统文件通知和单次合并接收，完整探针仍限真实前台及动画结束后。全局事件开关、第三方脚本、崩溃租约和实际覆盖范围见 [文档事件同步](文档事件同步.md)。真实手动操作已收到通知，自动化操作通常不触发 Notifier，不以脚本操作代替事件验收。

## 导出预设

参数模型、分类规则和字段过滤由 ExportPresetCatalog 维护；ExportPresetsStorage 将预设与四板块工作状态保存到独立的 export-presets.json，不扩展旧设置文件以避免回退时丢失数据。MainViewModel.Presets 在批量恢复期间抑制中间落盘，仍复用现有参数记忆。验证入口：`dotnet run --project tests/PSdodo.PresetTests -c Release -p:PublishSingleFile=false`，使用临时设置及拒绝 Photoshop/导出的替身服务。详细协议与回退依据见 [导出预设](导出预设.md)。
