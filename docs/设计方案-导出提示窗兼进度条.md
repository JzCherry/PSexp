# 设计方案：导出提示窗兼职导出进度条

状态：**已按本方案做完**。构建通过；自测全绿（含新增的三态文案断言）；三态几何 Δ=0 与"该画的有墨、该藏的没墨"用一次性离屏探针实测过（探针已用完删除，方法与结论写进开发指南），实测读数：`NoticeTitle 38,2.67 198.67x16.67`、`NoticeOpenGroup 0,0 59.33x18`、`NoticePath 38,26 266x18`、`NoticeProgress 0,64 340x4` 在各态一致，读数只换宽度（`0 个` 23.33 宽 / `4 / 12` 35.33 宽）右边缘不动。实机效果仍待你跑一次清单确认。

## 结论（一句话）

同一张浮动小窗从"导出真正开始"那一刻就出现，导出期间只显示进度、点不动；导出结束后它原地变成今天这张"点一下打开目录"的卡片——**位置、大小、列宽一个像素都不挪**。

## 1. 窗口只有三种状态

| 状态 | 左边图标位 | 主标题 | 右侧读数 | 底行 | 底部 4px 进度条 | 能不能点 |
|---|---|---|---|---|---|---|
| 导出中 | `···` | 正在导出 | `3 / 12`（有总数）或 `7 个`（无总数） | 输出目录 | 有：有总数按真比例，无总数走滚动动画 | **不能** |
| 成功 | 勾（今天的样子） | 已导出 12 个文件 | 打开目录 ›／打开上级 › | 输出目录 | 淡出 | 能，点一次打开目录 |
| 失败／被停止 | ✕ | 导出未完成／已停止 | （空，但位置照旧留着） | 输出目录 | 淡出 | 不能，同样秒数后自己关 |

- 主标题一律写短词（4 字），数字放右侧读数位，所以 364 DIP 宽的卡里不会有长句子被省略号咬掉。
- 底行从头到尾就是**同一个输出目录字符串**（导出开始时它已经知道了），所以结束时这行文字不变，看着最稳。
- 最后导出的文件名不往这张小窗放（主窗的日志和状态行已经有），小窗只做"进度 + 结果"，符合减法。

## 2. 什么时候出现、什么时候变

| 你做什么 | 它怎么反应 |
|---|---|
| 点"开始导出"，但预检没过（PS 没开、没画板、路径空、参数不合法） | **什么都不弹**（和今天一致，因为导出还没真开始） |
| 预检过了、脚本真跑起来 | 小窗在屏幕底部居中浮现，标题"正在导出"，进度条开始动 |
| 每导出成功一个文件 | 右侧读数变 `4 / 12`，进度条按比例长一格 |
| 导出成功结束 | 同一张卡原地换成"已导出 N 个文件 ＋ 打开目录 ›"，进度条淡掉，开始倒计时 |
| 点"停止等待"／导出失败／抛异常 | 同一张卡原地换成"已停止"／"导出未完成"，仍然点不动，倒计时后自己关 |
| 倒计时里鼠标划过它 | 暂停关闭，移开继续（今天的行为，不改） |
| 想把"完成提示"关掉 | 关了以后导出中也不再出现这张窗（一枚开关管这一整张窗，不加新开关） |

出现时机取 `IsExporting` 变 true 的那一刻（MainViewModel.cs:967，在预检和参数校验之后、脚本派发之前）。结束信号沿用今天的 `ExportCompleted`（只在真成功且文件数>0 时发，MainViewModel.cs:1002-1003），没收到它就当"没结果"处理。

## 3. 硬约束：绝不做第二次摆位

你以前定过规矩：元素出现之后再挪位、闪白、条宽重排都算缺陷。这条设计里最容易被踩，所以写法上有三条硬要求：

1. **窗口尺寸/位置一次算定**：沿用今天 `ShowOn` 的 364×92 与"屏幕工作区底部居中、留 8 DIP"算法，从出现到关闭不改 `Position/Width/Height`。状态切换只改文字、opacity、进度条 Value——这三个都不参与布局。
2. **右侧格子按最宽那组算，靠 opacity 交替而不是隐藏**：`打开目录 ›` 比 `3 / 12` 宽。如果用 `IsVisible=false` 收起来，Avalonia 会把它退出测量，列宽当场变小 → 中间文字可用宽度跟着变 = 你说的"条宽重排"。做法是两组内容常驻同一格，只显示一个（另一个 opacity=0，仍然占位测量），右侧一律右对齐贴卡右缘。切换时读数从同一个右边缘出发，Δ=0。
3. **进度条不进布局**：用现成 `ProgressBar`（Styles/Controls.axaml:340-343 已定义 Height=4、Foreground=Brush.Accent、Background=Brush.ProgressTrack，和主窗更新条 MainWindow.axaml:1311 同一套样式），作为跨两行两列的覆盖层贴卡片底边，`IsHitTestVisible=False`。它是覆盖层，不撑 Auto 行高；卡片圆角会裁住它（Controls/ContinuousBorder.cs:151 给子元素设了 Clip），不会露出直角。

这三条要用离屏渲染实测拿数字验：两种状态分别量窗口 Bounds 和 Grid 各列 Bounds，**要求完全相等**；不达标不算做完。图标位是固定 30×30，`···`／勾／✕ 三个都塞在同一格里 opacity 交替，所以图标也不会跳。

## 4. 进度数字从哪来（一份实现，不复制）

- 计数与文案沿用 `ExportedCount`（MainViewModel.cs:937）与 `FormatExportProgressText`（MainViewModel.cs:956），小窗拿它俩，不另写一套格式化逻辑。
- 总数目前**只有"全部画板导出"知道**（MainViewModel.cs:917 只在这个模式传 expected；快速导出虽算出 1 但没往下传）。所以：
  - 有总数 → 定量条 + `N / M`
  - 无总数（快速／图层／切片／选中画板）→ 不定量滚动条 + `N 个`
- 不定量动画不是新发明：主窗导出时今天就用同一枚不定量条（MainWindow.axaml:832）。两处共用同一份 VM 读数，属于同一个视觉语言。

## 5. "导出中点不动"怎么落

- `OpenNoticeDirectory.IsHitTestVisible = false`，转成结果态才放开。
- 刻意**不用** `IsEnabled=false`：样式里有 `Button:pointerover` 改背景/前景（Styles/Controls.axaml:101-106），禁用态也可能换色，那会变成"结束瞬间卡片闪一下"。命中关掉只掐事件，画面一模一样。
- 顺带说明：现在点击是靠 `_openDirectory` 委托（ExportNoticeWindow.axaml.cs:49），导出中它本来就是 null，所以"点了没反应"已经天然成立，命中关闭只是把悬停高亮也一起掐掉。

## 6. 设置：不加新开关

- "完成提示"这一行（MainWindow.axaml:1182）继续管这张窗，只是含义从"结束后的提示"变成"这张浮动窗"。
- **行标签文字我建议不动**：改成"导出提示"看着更准，但一个字变长可能重排设置行的列宽，属于你自己定的"第二次摆位"风险面。默认只改文档和 ToolTip 的说法。你要是坚持改字，我就一起实测列宽。
- "停留时间""点击打开"两枚开关职责不变，正交。

## 7. 唯一要你认的取舍

导出期间，屏幕底部会**常驻一张 364×92 的置顶小窗**（今天它只在结束后出现几秒）。它压住屏幕下沿一条；因为点不动、也不抢焦点（键盘 Esc 到不了它），导出没结束前你没法提前让它消失——只能等，或者把"完成提示"关掉。
好处是：主窗贴边收起、你正在 Photoshop 里干活时，屏幕上第一次有了一个看得见的导出进度。如果这一个月用下来你觉得挡手，第二批我再加一枚独立开关（导出不显示、只在结束显示）。

第二个小取舍：图层/切片导出前不知道总文件数，那两种模式的条是滚动动画，不是真百分比——不是猜不出来，是 Photoshop 没在跑完之前告诉我们数量。
