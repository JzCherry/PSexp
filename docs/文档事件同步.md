# 文档事件同步（实验接入）

此功能让 Photoshop 在有关操作发生后发出变化通知。PSexp 空闲时等待系统通知，不定时询问 Photoshop；未置顶时后台只合并变化，完整读取要求窗口真实获焦；用户置顶且窗口可见时，允许在没有焦点的情况下按事件更新。两种情况均等待收纳/展开动画结束。

## 用户得到什么

- 在 Photoshop 新建、切换、关闭文档等操作后，PSexp 可以知道文档信息需要更新。
- 未置顶时切回 PSexp 才读取最新名称、尺寸、目录、画板数量和切片状态；置顶时无需点回窗口，收到事件即可同步。托盘、最小化、收纳期间不读取。
- 若 PSexp 已在前台且收到外部变化，合并后允许再读一次，不受“同一次激活只读一次”的旧限制；没有新事件就不补读。
- “自动同步”（旧称“前台识别”）开关同时管理此接入，不新增轮询间隔或键鼠监听设置。关闭开关会停止通知并清理本应用的事件。
- 事件不是导出命令，不会自动重跑上次导出，也不创建用户文档。

它实现的是及时感知变化、按需同步。非置顶的 PSexp 在后台时不会立即读取全部信息；可见置顶窗口允许按通知读取。等待通知仍有少量内存、文件句柄和系统通知缓冲区开销，不能称为零占用；尚未做长期 CPU/内存基准测试。

## 数据链路

1. 初次成功完成符合置顶/焦点条件的 COM 识别后，通过 `probe/document_events.jsx` 注册 Photoshop 自带的 Notifier，不安装 UXP 面板插件。
2. Photoshop 触发对应事件时，运行本应用的 `notifier.jsx`。该脚本先检查活动租约，只向 `changed.signal` 覆盖写入时间戳和事件编号，不扫描图层、读取图像、激活窗口或运行导出。
3. `PhotoshopDocumentEvents` 使用 `FileSystemWatcher` 等待这个专用文件的系统通知，不监视 PSD 保存时间，也不扫描用户目录。因而未保存的操作也可以通知。
4. 多个原始文件事件合并为一次通知：收到事件后单次延迟 180 ms；新的事件重置这一次延迟。没有事件时定时器为 Infinite，没有周期唤醒。
5. 变化版本号保存在服务内。窗口通过 `CanReadForegroundDocument` 检查自动同步总开关、可见性、位置恢复、最小化、托盘和动画状态；之后用户置顶可直接获得资格，未置顶还需真实前台 HWND 和焦点。仅满足条件并等待绘制完成后才调用 COM 探针。方法名沿用历史命名，资格已扩展为可见置顶或真实前台。
6. 探针开始时记录本次已消费的变化版本。探针、导出或动画期间又发生变化，则保留为待同步；后续可处理时再合并读取。失败不会针对同一个版本无限重试；下一次正常激活仍会校准。
7. 导出前仍独立识别当前文档，通知不会取代导出前校验。

## 文件与生命周期

所有运行文件位于当前用户的 `%LOCALAPPDATA%/PSexp/DocumentEvents/`，不写入 Photoshop 安装目录，不打包个人运行文件进 Git。

| 文件 | 用途 |
| --- | --- |
| `notifier.jsx` | 从嵌入资源生成，内含本机通知路径的事件回调 |
| `active.lock` | PSexp 持有的活动租约；FileStream 使用 DeleteOnClose，正常关闭或进程句柄被系统回收后删除 |
| `changed.signal` | 最新变化的时间戳和事件编号，不包含图片数据、文档名称或文档内容 |
| `enabled-by-psexp.state` | 记住是否由本应用开启全局事件开关，以便恢复配置 |

PSexp 正常退出时先关闭文件通知和活动租约，再尽力注销本应用回调。托盘退出最多等待清理 1 秒，避免 Photoshop 忙碌时拖住退出；超时或强制结束后可能保留事件登记，但租约失效后回调不再写通知，下次接入会按同一个完整路径清理旧登记。关闭到托盘不等于退出，仍保留通知接收器。

Photoshop 重启后，在下一次符合条件的成功识别时根据新进程重新接入。系统文件通知发生错误时标记接收器不健康，下一次符合条件的接入重建；不启动后台补扫。

## 对其他脚本配置的保护

注销只匹配本应用回调的完整路径，文件名相同但路径不同的脚本不受影响。重复注册先移除这个路径的旧条目；移除失败则拒绝叠加重复回调。

`app.notifiersEnabled` 是 Photoshop 的全局开关：

- 已开启时，保持开启。
- 原来关闭且没有登记其他回调时，本应用可开启，并记录归属；移除自身后若没有其他回调，再恢复关闭。
- 原来关闭但已有其他回调时，不替用户将它们一并启用，事件接入失败并记录原因，继续使用前台识别。
- 使用期间新增第三方回调时，移除本应用后不关闭其全局开关。

## 事件覆盖与边界

登记清单见 `document_events.jsx`：打开、关闭、新建/选择文档、保存、图像/画布尺寸、裁剪、历史状态、撤销/重做、图层创建/删除/复制，以及画板和切片相关事件。部分名称由 Photoshop 版本决定，登记成功不代表已证明该版本一定发出该事件。

2026-11-02 在 Photoshop 2026 上验证：

| 项目 | 证据与结果 |
| --- | --- |
| 回调写入 → 系统通知 | 手动调用真实 Photoshop 内的回调后，接收版本变化，成功 |
| 用户手动新建、切换、关闭空白文档 | 收到 3 批真实通知，原始变化版本从 2 递增至 4、6、8，成功 |
| 空闲接收 | 最后操作之后，监听结束前约 80 秒无新增通知；这不是 CPU 基准测量 |
| 正常停止 | 租约删除；事件配置从原来的 false/0 恢复至 false/0，成功 |
| 其他脚本保护 | Node 回归检查覆盖全局关闭且有第三方回调、全局开启、重复注册及运行期间新增第三方回调 |
| 打开文件、另存为、画板与切片细节、撤销/重做 | 已登记，尚未逐项实机验证，不能宣称全部覆盖 |
| 进程被强制结束 | 使用系统 DeleteOnClose 机制；尚未通过实际强制结束 PSexp 验证 |

Adobe 明确说明，脚本内部发生的操作通常不触发 Notifier。本机通过 COM 自动化新建、切换和关闭临时文档也未触发通知，因此不能用这些调用替代真实手动操作的事件验收。第三方脚本、插件、系统通知丢失或 Photoshop 忙碌也可能造成遗漏；保留每次前台激活和导出前的完整识别作为兜底，不单凭事件缓存判断文档状态。

## 开发入口

- `Services/PhotoshopDocumentEvents.cs`：租约、通知接收、单次合并、注册和清理。
- `Resources/Scripts/probe/document_events.jsx`：事件注册与其他脚本保护。
- `Resources/Scripts/probe/document_change_handler.jsx`：轻量变化回调。
- `ViewModels/MainViewModel.DocumentEvents.cs`：待同步版本和按资格接入。
- `Views/MainWindow.axaml.cs`：置顶或焦点/绘制/动画门槛及忙碌结束后的补处理。
- `tests/DocumentEvents.test.mjs`：执行 `node tests/DocumentEvents.test.mjs` 检查配置保护。

日志写入 `%LOCALAPPDATA%\PSexp\Logs\psx.log`，以 `[document-events]` 标记。`subscribed` 表示登记完成，`changed version=...` 表示收到变化；只有消费变化的日志和实际探针结果，才能证明完整读取已执行。不要将“收到通知”与“已经完成同步”混为一谈。

## 手动刷新与权限

手动刷新和自动识别都只通过 COM 内部读取，不再因失败派发外部 `.psjs` 文件。权限不一致会显示明确的连接权限提示；一般读取失败保留上次信息并标注“同步中断”，不能理解成后台正在持续重试。真实管理员启动已验证能自动切回同账号普通权限，后续文档事件和 COM 识别正常。主动导出的 UXP 工作流保留；它执行期间仍可能使 Photoshop 成为前台，这种情况由焦点租约处理：用户没有动手就把前台拿回 PSexp，动了手就不抢（实现见开发指南）。

2026-11-02 对当前 PSexp 进程的一次约 4 秒后台静置采样：进程 CPU 时间计数未增长，工作集约 224.1 MiB、专用内存约 179.9 MiB。这是整个应用（含界面、渲染、运行时和缓存）的短时读数，既不是事件监听组件单独的占用，也不是长期或峰值基准；没有测量 Photoshop 回调自身的 CPU 时间。监听不注册全局快捷键或键鼠钩子；完整 COM 探针仍会短暂使用 Photoshop 脚本线程，不能承诺对操作完全零影响。


## 置顶同步变更的验证边界

置顶启用时重置一次同步资格；其后仅新通知触发读取，未置顶则继续等待焦点。标题栏、设置和托盘使用 IsAlwaysOnTop，导出或贴边内部临时 EffectiveTopmost 不开启后台同步。此次变更只编译和审查代码，没有运行用户 Photoshop 交互测试；前文的手动事件记录属于原有接入验证，不能当作这次置顶行为的实机验证。脚本抑制事件、Photoshop 关闭/重启、系统通知遗漏仍可能需要手动刷新或下一次焦点校准。
